# Melvor 对标材料与制造体系蓝图

日期：2026-07-29

## 目标

本设计用于建立一套完整的材料与制造体系对标蓝图。目标不是先简化，而是先保留对标游戏的完整系统骨架、依赖关系、数值字段和模块覆盖范围，再在后续版本中根据本游戏的修仙题材逐步替换、删减或特化。

本文件基于官方 Wiki 页面进行结构分析：

- Mining: https://wiki.melvoridle.com/w/Mining
- Smithing: https://wiki.melvoridle.com/w/Smithing
- Crafting: https://wiki.melvoridle.com/w/Crafting
- Farming: https://wiki.melvoridle.com/w/Farming
- Herblore: https://wiki.melvoridle.com/w/Herblore

## 边界

需要完整保留：

1. 模块数量与模块职责。
2. 材料链路拓扑。
3. 配方字段结构。
4. 解锁等级、动作时间、经验、价值、材料消耗、稀有度、掉率等数值字段的位置。
5. “一个材料服务多个职业”的交叉消耗设计。
6. 后续可以导入精确授权数据的字段结构。

不会直接写入：

1. 对标游戏的整套公开 Wiki 表格原文。
2. 对标游戏的完整可识别物品名、配方名、图标、文案和逐项数值表。
3. 只替换名称但保持竞品完整数据集的配置。

如果后续有合法授权的结构化数据文件，可以通过导入器填充本蓝图保留的字段位。

## 对标体系总览

| 对标模块 | 主要职责 | 我们游戏承接页面 | 缺失处理 |
| --- | --- | --- | --- |
| Mining | 产出矿石、精华、宝石、特殊矿脉 | 采矿 | 完整承接；新增燃料/精华/宝石掉落表 |
| Smithing - Bars | 矿石熔炼成金属锭 | 炼器或新增“炼材”子页 | 先合并到炼器页 |
| Smithing - Gear | 金属锭制作武器、护甲、弹药部件 | 炼器 | 完整承接装备模板，但命名修仙化 |
| Crafting - Armour | 皮革/龙皮/木材制作远程或轻甲装备 | 炼器、战利品 | 缺失的远程装备先转为轻甲/法袍/护具 |
| Crafting - Jewellery | 宝石 + 贵金属锭制作戒指、项链 | 炼器、饰品 | 转为灵戒、法坠、玉佩、阵眼 |
| Crafting - Bags/Urns | 技能消耗品、容器、功能道具 | 符箓、阵法、炼器 | 先合并到符箓/阵法 |
| Farming | 种子种植食材、药草、树木 | 灵田 | 完整承接；树木类可合并到灵田或伐木 |
| Herblore | 药草 + 二级材料制作技能药水 | 炼丹、符箓 | 转为丹药、符箓助剂、技能增益道具 |

## 完整依赖结构

### 采矿到锻造

对标结构：

```text
矿脉 -> 矿石 -> 金属锭 -> 装备 / 弹药部件 / 制作材料 / 升级材料
```

本游戏结构：

```text
灵矿脉 -> 灵矿石 -> 灵材锭/器胚 -> 法器 / 护具 / 阵器 / 符器部件
```

必须保留的链路特征：

- 低阶金属由 1-2 种基础矿石合成。
- 中阶开始引入通用燃料瓶颈。
- 高阶继续增加燃料消耗或副矿消耗。
- 贵金属独立用于饰品和升级，不只服务装备。
- 特殊矿脉用于高阶或扩展内容，不和普通矿石完全等价。

### 宝石到饰品

对标结构：

```text
采矿随机宝石 -> 宝石稀有度梯度 -> 贵金属锭 + 宝石 -> 戒指 / 项链
```

本游戏结构：

```text
灵矿随机玉石 -> 玉石稀有度梯度 -> 贵金属灵锭 + 玉石 -> 灵戒 / 法坠 / 玉佩 / 阵眼
```

必须保留的链路特征：

- 宝石从采矿系统外溢到制作系统。
- 宝石有明显稀有度梯度。
- 同一宝石可以进入不同饰品类型。
- 贵金属锭与宝石绑定，形成采矿和制作之间的稳定需求。

### 灵田到炼丹

对标结构：

```text
种子 -> Farming -> 药草 -> Herblore -> 药水
药草 + 二级材料 -> 某职业增益药水
```

本游戏结构：

```text
灵种 -> 灵田 -> 灵草 -> 炼丹/符箓 -> 丹药/符箓助剂
灵草 + 二级材料 -> 某系统增益道具
```

必须保留的链路特征：

- 药草主要来自种植，但允许战斗或其他系统补充。
- 每个增益道具绑定一种药草和一种或多种二级材料。
- 二级材料来自目标系统本身，例如采矿药剂消耗矿石，钓鱼药剂消耗鱼类。
- 同一个药剂/丹符可以有多阶效果，材料类型不变，强度或使用次数提升。

### 战斗材料进入制造

对标游戏的 Crafting 和 Herblore 会大量吃战斗产物，例如皮革、龙皮、骨头、怪物副产物。我们当前战斗材料不足，因此需要把战斗掉落补成制造体系的一部分。

本游戏结构：

```text
战斗 -> 妖兽材料 / 残魂 / 妖丹 / 鳞甲 / 骨爪 -> 炼器 / 炼丹 / 符箓 / 阵法
```

必须保留的链路特征：

- 战斗材料不只出售，也要进入核心生产。
- 轻甲、护具、特殊符箓和部分丹药都应消耗战斗材料。
- 战斗材料与生活技能材料共同构成配方，避免单系统闭环。

## 数值字段对照

为了后续实现一一对应导入，每个采集点、材料和配方都必须保留以下字段：

### 采集点字段

| 字段 | 说明 | 我们游戏对应 |
| --- | --- | --- |
| `sourceId` | 采集点 ID | 矿脉/林地/药田/钓点 ID |
| `sourceName` | 采集点显示名 | 修仙化名称 |
| `sourceType` | 资源类型 | mining/herb/fishing/woodcutting/farming |
| `requiredLevel` | 解锁等级 | 技能等级或境界等级 |
| `actionSeconds` | 单次动作时间 | 当前采集动作时间 |
| `baseXp` | 基础经验 | 技能经验 |
| `respawnSeconds` | 资源恢复时间 | 有限资源点恢复或库存恢复 |
| `baseValue` | 基础价值 | 售价/系统估值 |
| `dropTableId` | 掉落表 ID | 掉落配置引用 |

### 材料字段

| 字段 | 说明 | 我们游戏对应 |
| --- | --- | --- |
| `itemId` | 材料 ID | 修仙化 ID |
| `sourceRef` | 对标来源槽位 | 保留对照关系 |
| `materialType` | 材料二级类型 | ore/bar/gem/herb/seed/hide/bone/fuel/essence |
| `tier` | 阶级 | 制作与图标阶级 |
| `rarityWeight` | 稀有度权重 | 掉率或抽取权重 |
| `sellValue` | 售价 | 灵石价值 |
| `entersInventory` | 是否进背包 | 背包显示规则 |
| `visualFamily` | 视觉族群 | 图标生成字段 |

### 配方字段

| 字段 | 说明 | 我们游戏对应 |
| --- | --- | --- |
| `recipeId` | 配方 ID | 炼器/炼丹/符箓/阵法配方 |
| `skillId` | 制作职业 | production skill |
| `requiredLevel` | 解锁等级 | 技能等级 |
| `baseSeconds` | 制作时间 | 生产耗时 |

| `outputQuantity` | 产出数量 | 产出数量 |
| `ingredients` | 固定材料消耗 | 配方材料 |

## 实现策略

### 第一阶段：建立完整数据壳

先新增数据表，不启用全部内容：

- `content/material-taxonomy.js`
- `content/material-sources.js`
- `content/manufacturing-parity.js`
- `content/parity-import-schema.js`

这些文件只定义结构、槽位、字段和修仙化 ID，不直接写入对标游戏完整逐项数据。

### 第二阶段：填充修仙化等规模数据

按完整槽位填入本游戏原创材料：

- 采矿材料链完整覆盖。
- 熔炼材料链完整覆盖。
- 炼器模板完整覆盖。
- 宝石饰品链完整覆盖。
- 灵田药草链完整覆盖。
- 丹符增益链完整覆盖。
- 战斗材料链补齐 Crafting 和 Herblore 所需二级材料。

### 第三阶段：接入现有页面

按用户要求处理缺失功能：

1. 对标游戏没有、而本游戏已有的系统，暂时不被本轮材料链驱动。
2. 对标游戏有、而本游戏没有的系统，产物合并到现有页。
3. 优先承接到采矿、炼器、灵田、炼丹、符箓、战斗战利品。

### 第四阶段：精确数据导入位

如果后续提供授权的结构化数据，可以按以下方式导入：

```text
source row -> parity sourceRef -> localized itemId -> localized recipeId -> game content module
```

导入前必须进行：

- ID 去重。
- 名称本地化。
- 分类映射。
- 页面承接映射。
- 背包显示检查。
- 配方闭环检查。

## 闭环检查规则

每次填充或导入材料时，需要检查：

1. 每个材料至少有一个来源，除非它是纯合成产物。
2. 每个普通材料至少有一个用途，除非明确标记为货币或系统包。
3. 每个配方的材料都必须能通过现有页面获得。
4. 每个战斗材料至少进入一个制作系统。
5. 每个宝石至少进入一个饰品或丹符配方。
6. 每个药草至少进入一个丹药/符箓配方。
7. 每个种子至少能种出一个材料。
8. 每个金属锭至少能制作一组装备或部件。
9. 每个页面新增产出后，必须有背包 tooltip 显示。
10. 每个图标生成项必须有 `visualFamily` 与 `iconPromptKey`。
