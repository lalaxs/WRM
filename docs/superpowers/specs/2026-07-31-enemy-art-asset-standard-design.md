# 敌人形象美术素材规范设计

日期：2026-07-31

## 1. 目标

为游戏内全部敌人建立统一、可批量生产、可在竖屏小尺寸战斗卡中识别的正式美术规范。

规范覆盖：

- 妖兽、灵兽、飞禽、虫兽；
- 灵体、怨魂、异兽；
- 傀儡、机关兽、石木造物；
- 邪修、盗修、守卫、仙将等人形敌人；
- 巨型首领、天魔、法相和抽象高阶存在。

正式风格名为：

```text
enemy-v1-no-outline-xianxia
```

中文名称为“无描边轻仙侠·萌怪剪影风”。

该风格借鉴《银河奶牛放置》在挂机战斗界面中的紧凑造型、轮廓可读性和轻量表现，但不复刻其太空题材、具体形象或过度搞怪气质。最终表达服务于本游戏的修仙世界、浅紫界面与现有 `v4-no-outline` 道具图标体系。

## 2. 已选择的方向

设计阶段比较过三种方向：

1. 完全偏向可爱卡通：小尺寸清楚，但容易低幼并削弱修仙危险感；
2. 无描边轻仙侠·萌怪剪影风：普通怪可爱、精英锐利、首领有压迫感；
3. 国风半厚涂：表现力强，但与当前扁平道具和轻量 H5 界面差异过大，生产成本也更高。

正式采用第二种方向。

## 3. 数据来源与内容边界

所有实际敌人素材必须来自 `content/combat.js` 中已经存在的敌人：

```text
enemyId + name + tier + rank + region
```

允许增加 `visualFamily`、`artDetail` 或同等作用的美术说明，用于把现有名称转化为可绘制的形象。美术说明不得：

- 新增敌人；
- 修改现有 `enemyId` 或名称；
- 擅自增加剧情身份；
- 创造游戏中没有定义的新能力；
- 给武器、法宝或组织添加未经批准的专有名称。

抽象敌人以名称、阶级、所在区域和现有战斗定位为解释上限。

## 4. 统一构图

### 4.1 共通规则

- 单个敌人主体，透明背景。
- 无黑色描边、无线稿、无相框、无场景、无地面底座。
- 默认四分之三视角，朝向画面左前方，与我方形成对阵关系。
- 主体视觉中心居中。
- 普通和精英主体占画布约 76%–86%。
- 首领主体可占画布约 82%–90%。
- 耳、角、翼、尾、武器和冠饰等关键轮廓不能贴边或被截断。
- “可爱”来自圆润概括、简化比例和清楚姿态，不使用星星眼、吐舌、腮红等低幼表情。
- “危险感”来自姿态、尖锐结构、体型与色彩对比，不依赖黑边、血腥或满屏特效。

### 4.2 各类敌人构图

| 类型 | 构图要求 |
| --- | --- |
| 妖兽、灵兽 | 完整身体；头部略放大；四肢和尾巴适度简化 |
| 飞禽、虫兽 | 完整身体；翼展、尾羽或甲壳形成主剪影；避免细碎触须 |
| 灵体、怨魂 | 完整悬浮轮廓；上实下虚；能量尾部必须连接主体 |
| 傀儡、机关兽 | 完整身体；以大块岩石、木材或机械结构表达材质 |
| 邪修、盗修、守卫、仙将 | 头部至膝部的四分之三身；武器只保留最有识别力的部分 |
| 巨型首领、法相 | 可使用半身或压缩后的完整身体；仍须保持单主体和清楚边界 |

人形敌人不画成证件照，也不采用与玩家角色相同的精细换装立绘。其服装、发冠、兵器和站姿必须经过扁平化概括。

## 5. 形状语言

- 妖兽：圆弧身体配少量尖锐攻击结构。
- 飞禽、虫兽：翼展、尾羽或甲壳作为主剪影。
- 灵体、怨魂：连续的悬浮形态，上实下虚。
- 傀儡、机关兽：方块、梯形和硬质切面。
- 人形敌修：斗篷、发冠、兵器与站姿区分身份。
- 仙将、天魔、法相：较长的纵向比例，加宽肩部或背部结构。

同一敌人族群可以共享身体语言，但不能只靠换色区分成员。

## 6. 等级视觉分层

等级不依赖 UI 标签、边框或单纯换色，必须仅看形象就能感受到强弱。

| 等级 | 造型 | 色块 | 特效 |
| --- | --- | --- | --- |
| 普通 | 单一明确剪影，只保留一个核心特征 | 4–6 | 不使用外部光效 |
| 精英 | 增加一个主导结构，如巨角、冠羽、重甲或重兵器 | 5–8 | 允许一处与身体相连的灵气、雷纹或火焰 |
| 首领 | 独立剪影；体型更宽、更高或明显不对称 | 7–10 | 允许一组受控效果，但不能遮住身体 |

补充要求：

- 禁止用普通怪换色冒充精英或首领。
- 精英最多增加一个主视觉特征。
- 首领复杂度集中在头冠、核心、武器或背部结构之一。
- 普通怪姿态偏自然或警觉；精英偏攻击准备；首领偏稳定、居高临下。
- UI 已显示阶级，素材不添加皇冠、星级、角标或阶级文字。
- 所有灵气与元素效果必须连接主体，不生成悬空粒子和背景法阵。

## 7. 色彩与渲染

### 7.1 色彩

- 普通敌人使用一个主色、一个辅色和 2–4 个明暗或局部色。
- 精英与首领可以增加一个高识别度强调色。
- 主色与敌人名称、属性和区域一致，例如雷系蓝紫、火系朱红、岩石灰褐、魂系青紫。
- 禁止全身高饱和荧光色。
- 鲜艳色只用于眼睛、核心、雷纹和火焰等焦点。
- 当前战斗卡背景偏白、浅粉，主体外缘不得大面积接近白色。

### 7.2 渲染

- 无描边、无线稿、无黑色外轮廓。
- 使用大块平涂，最多一层亮面与一层暗面。
- 不使用厚涂笔触、复杂材质噪声、真实毛发或金属反射。
- 不使用落在透明画布上的投影。
- 灵体允许局部半透明，但主体核心必须保持实色。
- 雷、电、火、魂气使用连接主体的完整色块，不使用雾状粒子和大面积泛光。
- 五官只服务情绪，不追求写实。
- 人形敌人的服装和武器只保留身份所需结构，避免复杂花纹和衣褶。

## 8. 资产规格

| 规格 | 用途 | 要求 |
| --- | --- | --- |
| 512×512 PNG | 美术母版与后续调整 | RGBA、透明背景、完整主体 |
| 256×256 PNG | 游戏正式运行资源 | RGBA、由母版高质量缩放 |
| 104×104 预览 | 桌面战斗框验收 | 不作为正式资产 |
| 84×84 预览 | 竖屏战斗框验收 | 不作为正式资产 |

正式运行资源使用现有 `enemyId` 命名：

```text
assets/enemy-portraits/256/{enemyId}.png
```

示例：

```text
assets/enemy-portraits/256/thornHare.png
assets/enemy-portraits/256/stonePuppet.png
assets/enemy-portraits/256/rogueCultivator.png
```

## 9. 正式提示词模板

```text
用途：修仙放置手游的小尺寸战斗敌人形象。
数据来源：游戏现有敌人 {enemyId}，名称 {name}，境界阶层 {tier}，阶级 {rank}，区域 {region}。
风格：enemy-v1-no-outline-xianxia，无描边轻仙侠·萌怪剪影风。
主体：正好一个敌人，{visualFamily}，{artDetail}。
构图：正方形透明素材，四分之三视角，朝向画面左前方，主体居中，占画布 {occupancy}，关键轮廓完整。
渲染：简洁扁平矢量插画，大块纯净色面，最多一层亮面和一层暗面，主色清楚。
等级表现：{rankArtDirection}。
小尺寸要求：在 104px 和 84px 战斗框中仍能通过轮廓、姿态和主色辨认。
限制：无描边、无线稿、无场景、无底座、无文字、无阶级标识、无散落粒子、无额外角色、无水印。
```

统一负向提示词：

```text
不要描边，不要黑色轮廓，不要线稿，不要复杂渐变，不要写实厚涂，
不要照片感，不要 3D 渲染，不要场景背景，不要地面底座，不要相框，
不要文字，不要等级标识，不要血腥，不要散落粒子，不要大面积光晕，
不要多个敌人，不要多余宠物，不要裁断关键轮廓，不要水印。
```

如果生成工具不能直接交付可靠透明背景，可以使用与主体无冲突的纯色中间背景；正式入库前必须转换为透明 RGBA。

## 10. 首批风格验证样张

首批只使用游戏现有敌人，共七个：

| enemyId | 名称 | 游戏定位 | 验证重点 |
| --- | --- | --- | --- |
| `thornHare` | 棘刺兔 | 一阶普通妖兽 | 低阶萌怪、强剪影 |
| `stonePuppet` | 岩石傀儡 | 二阶普通傀儡 | 硬质色块与傀儡感 |
| `soulMoth` | 噬魂蛾 | 四阶普通虫灵 | 翅膀、灵体与暗色表现 |
| `rogueCultivator` | 邪修 | 二阶普通人形 | 敌修的四分之三身构图 |
| `thunderJudge` | 雷罚使 | 五阶精英 | 精英人形与受控雷纹 |
| `earthVeinApe` | 地脉猿王 | 二阶兽类首领 | 首领体型和压迫感 |
| `myriadLawAvatar` | 万法化身 | 八阶高阶首领 | 法相、复杂度上限与仙侠感 |

首批造型解释只用于视觉化现有名称：

- 棘刺兔：兔形妖兽，以背部短棘作为唯一攻击特征。
- 岩石傀儡：由少量完整岩块构成的紧凑人形傀儡。
- 噬魂蛾：青紫暗色蛾形虫灵，以宽翼和实色魂核为焦点。
- 邪修：深色短袍、未命名护身器物与戒备姿态。
- 雷罚使：蓝紫人形精英，雷纹与身体或兵器相连。
- 地脉猿王：厚重猿形首领，岩质突起与地脉色面集中在肩背。
- 万法化身：单一人形法相核心，数片相连法相结构形成高阶轮廓。

这些解释不新增剧情、技能或专有装备。

## 11. 原型生产流程

1. 每个敌人独立生成，不在一次生图中拼入多个敌人。
2. 每张图使用相同风格模板，并加入该敌人的现有数据与已批准造型解释。
3. 生成结果先作为原型，不直接接入 `ui.js`。
4. 去除中间背景，输出 512px 透明母版。
5. 居中并缩放为 256px 预览。
6. 生成同一接触表中的 256px、104px、84px 和浅粉战斗卡背景预览。
7. 用户可整批通过，也可指定单张重做。
8. 风格整体通过后，首批合格素材才能迁移到正式运行目录并建立 UI 映射。

原型目录：

```text
docs/art/enemy-prototypes/2026-07-31-enemy-v1/
```

每个敌人的原型文件：

```text
{enemyId}-source.png
{enemyId}-preview.png
```

总览文件：

```text
enemy-v1-contact-sheet.png
```

## 12. 淘汰与修订

出现以下任一问题必须单张重做：

- 不是游戏现有敌人，或与现有名称明显不符；
- 多个主体、额外宠物、额外人物或分身；
- 黑边、线稿、厚描边；
- 写实、厚涂、3D 或照片感；
- 主体偏心、贴边或关键轮廓被裁断；
- 普通怪复杂度超过精英或首领；
- 84px 下无法辨认主要轮廓；
- 人形敌人缩得过小，或武器抢占主体；
- 透明边缘存在白边或色边；
- 七张之间出现明显不同的渲染风格；
- 为敌人添加了未经批准的剧情或装备设定。

修订时一次只处理一个问题，例如只改构图、只降低细节或只改变主色。

## 13. 质量检查

### 13.1 自动检查

- 512×512 与 256×256 尺寸正确；
- 文件为 PNG RGBA；
- 四角透明；
- 可见主体占画布 76%–90%；
- 视觉中心偏差不超过画布 3%；
- 文件名与现有 `enemyId` 完全一致；
- 原型名单中的 `enemyId` 均存在于 `content/combat.js`。

### 13.2 人工检查

- 七个敌人仅靠轮廓和主色即可区分；
- 普通、精英和首领的强弱关系成立；
- 妖兽、虫灵、傀儡和人形看起来属于同一款游戏；
- 与无描边道具风格协调，但敌人拥有更强的姿态和生命感；
- 放在当前浅粉战斗卡后没有轮廓消失；
- 104px 与 84px 下仍能辨认身份；
- 没有多余故事、文字、阶级徽章或背景装饰。

## 14. 本阶段边界

首批样张阶段只交付规范、七张原型和接触表。

本阶段不：

- 批量生成全部敌人；
- 修改敌人数值或内容；
- 修改敌人名称和 `enemyId`；
- 覆盖当前战斗界面；
- 修改 `ui.js` 或正式发布目录；
- 将未获批准的原型当作正式资产。

只有在用户明确确认整批或指定单张合格后，才进入正式接入设计与实施。
