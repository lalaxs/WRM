# 功法验证池补齐与引擎词表补强设计

日期：2026-08-10  
状态：补充设计稿（承接 `2026-07-30-technique-sect-builds-design.md`）  
范围：现有实装与设计稿 32 本验证池的对齐、效果词表补齐、槽位门控、单人/队伍结算语义统一、分阶段落地顺序  
不包含：神话功法、正式服最终数值、图标与动画  
**系统边界（已收敛）**：只做功法。不做天赋/心法树、装备标签共鸣纵深、图鉴/收集乘区、生活技能回流绑功法，以及任何「IdleOn 七层完整度」路线。

## 1. 背景与目标

当前实装（`content/techniques.js`）只有 **16 本**（10 主动 / 6 被动）。学书、升级、方案装载、条件释放与单人战主链路可用，但：

1. 相对设计稿验证池 **32 本**（20 主动 / 12 被动）与路线图 **76 本**，内容不足。
2. 效果词表过窄：缺护盾、群攻、DoT、净化、条件被动闭环；多数主动是倍率变体。
3. 槽位固定 3+3，未按境界门控。
4. 等级缩放与设计不一致（实装约主动 3% / 被动 2%，设计为 2% / 1.5%）。
5. 队伍战弱化：回气、被动乘区、标签增伤、真气/CD 等语义未与单人战对齐。

本补充设计目标：

- **不重写** 2026-07-30 主设计，而是给出「从 16 → 验证池 32」的可执行对齐方案。
- 先补 **引擎效果词表与槽位规则**，再补内容，避免内容先堆后返工。
- 使无门派即可组成输出 / 治疗 / 护盾 / 回气 / 控制五类方案，并为六门派各留 1 条可辨构筑轴。

## 2. 原则

1. **设计稿优先**：验证池以主设计 §18 名单为准；现有实装能映射的保留 ID 或改名映射，不能映射的退役或改职能。
2. **引擎先于内容**：新增 effect type / status 未落地前，不批量写死数值到内容表。
3. **差异化靠功法机械模式，不靠外挂系统**：每本新增功法必须新增或强化至少一种效果模式或标签闭环；禁止用天赋/装备共鸣/图鉴来「补构筑」。
4. **传说暂缓**：验证池第一阶段不含传说/神话；星落阵诀等超标内容降级或延后。
5. **存档兼容**：已学功法 ID 尽量保留；必须改名时提供 `techniqueId` 别名迁移表。

## 5. 引擎效果词表（必须先落地）

验证池新增内容依赖以下 effect / status。未实现前，对应功法只允许进内容表草稿，不允许进战斗结算。

### 5.1 主动 effectType

| effectType | 用途 | 首轮消费方 |
|---|---|---|
| `attack`（已有） | 单体/多段伤害；扩展 `hits`、`defenseIgnore`、`status` | 碎石拳、回风斩、破甲指等 |
| `heal`（已有，需改公式） | 改为混合：`attackFactor + maxHpRatio` | 回春术、止血、宁神曲 |
| `restoreQi`（已有，需改） | 支持 `maxQiRatio`，不只固定 `amount` | 小周天吐纳术 |
| `shield`（**新增**） | `defenseFactor + maxHpRatio`；写入目标 `shield` | 护体罡气、灵甲符阵 |
| `aoeAttack`（**新增**） | 对最多 4 敌；乘主设计 §3.7 目标数系数 | 炎雷阵 |
| `applyStatus`（**新增或统一**） | 仅上状态、可带轻伤 | 迷心眸；灼烧/毒附在 attack 上亦可 |
| `purge`（**新增**） | 移除 1 个可净化控制/减益 | 宁神曲 |
| `guard`（**新增**） | 替伤：下一次合法单体攻击转移 | 灵契护主 |
| `beastAttack`（**新增**） | 出战灵兽立即攻击；无兽则不可释放 | 裂阵兽吼 |
| `partyDamageBuff`（**新增**） | 全队伤害提高；可读好感快照 | 同心引 |

### 5.3 状态语义（与主设计 §4.3 对齐，首轮最少集）

首轮必须可结算：

- `burn`（灼烧）、`poison`（中毒叠层）、`slow`（迟缓）
- `weaken`（虚弱/命中降低，供迷心眸）
- 护盾值（非状态，属性字段）
- `purgeable` 标记：控制与指定减益可被净化

可延后：流血、沉默、眩晕完整链、魅惑改目标（迷心眸首轮用虚弱即可，醉红尘留给下一批）。

### 5.4 等级缩放纠正

对标 MWI 后：

- 功法等级上限 **200**（MWI Ability 同技能表）
- 旧「主动 +2%/级、被动 +1.5%/级、上限 20」总强度预算映射到 **Lv100**
- 实装：`1 + bonusAt100 × (level - 1) / 99`（主动 0.38，被动 0.285），延伸至 Lv200
- 概率 / CD / 消耗 / 段数默认不随等级成长
- 内容表逐步引入显式 `levelScaling[]`；过渡期全局公式先改系数

### 5.5 释放条件补齐

补全 `selfMissingBuff` / `allyMissingShield` / `enemyMissingStatus` 等选项列表（当前 UI 空选项）。

首轮条件类型最低集：

- 始终
- 自身气血 / 真气低于比例
- 队友气血低于比例
- 敌人数量不少于 N
- 敌人缺少指定状态（灼烧/中毒/迟缓/迷心）
- 自身或队友缺少护盾
- 灵兽存活
- 全队缺少指定增益（同心引）

## 6. 槽位门控（对齐主设计 §2）

| 境界 | 主动槽 | 被动槽 |
|---|---:|---:|
| 炼气 | 1 | 1 |
| 筑基 | 2 | 2 |
| 金丹 | 3 | 3 |
| 元婴 | 3 | 4 |
| 化神及以后 | 3 | 5 |

实现要点：

- `combat-loadouts` 存档结构改为被动数组长度 **5**（未解锁槽固定 `null` 且不可写入）。
- 主动仍长度 3；未解锁槽 UI 锁定，自动释放跳过。
- 境界回退（若存在）时，超出槽位的功法卸下回藏书，不删除已学。
- 装备页功法子页按解锁数渲染槽位，避免「练气满 3 主动」的假进度。

## 7. 单人战 / 队伍战语义统一

同一套 `TechniqueDefinition` + 同一套 effect 解释器；禁止队伍战「只吃 attack/heal」。

首轮队伍战必须支持：

1. 真气消耗与冷却（高精度 tick 与单人一致）
2. `restoreQi` / `heal`（混合公式）/ `shield`
3. 被动：标签增伤、治疗强度、护盾强度、命中、暴击、控制抗性、疾影
4. DoT 周期结算
5. 群攻目标选择与系数
6. 条件谓词（含队友/全队）

可第二批再齐：替伤完整交互、好感快照增伤精细对照、灵兽替伤与百兽奔袭。

离线批量结算必须复用同一解释器或同一事件日志回放，满足主设计验收 #11。

## 9. 掉落与获取（验证池）

- 无门派 8 主动 + 6 被动：沿用现有区域掉落表扩表，保证炼气～筑基能凑齐基础五类。
- 门派各 2 主动 + 1 被动：门派未开放前，允许「散修奇遇 / 区域稀有掉落」低概率获取，避免系统空转；门派开放后改为稳定渠道。
- 每本验证池功法必须有：`bookItemId`、至少 1 个获取源、推荐释放条件。

## 12. 验收清单（本补充专属）

规则：
