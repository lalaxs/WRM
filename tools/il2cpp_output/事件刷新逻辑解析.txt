「某某宗女修修炼手札」事件刷新逻辑解析  （基于 Il2CppDumper 还原的 dump.cs）
═══════════════════════════════════════════════════════════════════

【先说人话】
这个游戏里"事件"= 游戏世界每天发生的事（遇到人、触发剧情、修炼突破、人际关系变化等）。
"刷新" = 游戏时间每走一天，就重新检查"今天该发生什么"，并按规则把事件塞进队列、显示给玩家。
整件事由一个总控制器 root 类统一调度，数据存在几个列表里。

───────────────────────────────────────────────────────────────────
一、谁负责这件事
───────────────────────────────────────────────────────────────────
类 root（挂在游戏场景里的"大脑"，继承 MonoBehaviour）：
  - mainloop()        主循环协程（游戏时间在这里一帧帧推进）
  - Update()          Unity 每帧回调（负责计时、检测是否到"下一天"）
  - addday()          天数 +1（时间往前走一格）
  - dayevent()        每日事件检查（核心刷新入口）
  - ondayevent()      每日事件的处理器
  - doevent(int[] temp)  执行单个事件（temp[0]=事件ID，后面是参数）
  - act1event(person) 与某个角色互动时触发的事件
  - addeventlove(person) 给某角色添加"感情/关系"类事件
  - waittime0(time,func,clone)  延时器：等 time 秒后，调用名为 func 的方法（"过一会儿再刷新下一步"靠它）
  - getpost(url,func,...)  向服务器要数据，回来后调用名为 func 的方法（"联网拉新事件"靠它）
  - savegameloop()    自动存档循环

───────────────────────────────────────────────────────────────────
二、事件数据存在哪（几个关键列表）
───────────────────────────────────────────────────────────────────
root.events        List<string[]>   活动事件队列：每个事件 = 一个字符串数组（像一段小脚本/参数表）
root.mday          int[]            **月天数表**（[0,31,28…31]），供 addday 翻月；不是事件 ID 日程
root.loglist       List<int[]>      事件日志
root.hislist       List<int[]>      历史日志
person.history     List<int[]>      每个角色自己的人生履历（每件事 = int数组：[类型,天数,对象ID...]）
person.act1 / act1day              该角色被安排的"行动事件"ID 和预定天数

配置表 dns（静态数值总表）里和事件相关的：
  dns.fami_act1day  int[]   每个家族每日行动配额
  dns.act4day       float   玩家每日行动次数上限
  dns.npclog        int[]   事件 ID 池（叙事文案走加密 GetString）
  dns.s_day/pet_day int     剑修/灵宠相关天数
  dns.myurl         string 服务器地址（联网事件从这儿来）

───────────────────────────────────────────────────────────────────
三、一次"事件刷新"的完整流程（设计骨架）
───────────────────────────────────────────────────────────────────
1) 启动：startgame() → 开启 mainloop() 协程，游戏时间开始走。
2) 计时：Update() 每帧检查；mainloop() 到点就调用 addday() 把天数 +1（用 mday 翻月）。
3) 每日检查：addday() 之后触发 dayevent()：
     · 关系网 getpe ∩ cans 过滤；
     · randomlevel() 按约 1～2 抽随机事件；
     · 把抽到的事件拼成 int[] temp（事件ID + 参数）。
4) 执行：doevent(temp) 经加密字典解释，显示给玩家。
5) 延时刷新：若一个事件要"过一会儿再走下一步"，就调用
     waittime0(秒数, "下一步方法名", 对象) —— 等 N 秒后自动调用那个方法名，实现分步/连环事件。
6) 角色事件：玩家和某角色互动 → act1event(p)/addeventlove(p) → 写入 person.history 和全局日志。
7) 联网事件：定时或登录时 getpost(dns.myurl, func, ...) 找服务器要新内容，
     服务器返回后回调名为 func 的方法，把新事件注入 events 队列。
8) 收尾：事件结果经 addinfohistory() 入档，showhistory() 展示给玩家。

───────────────────────────────────────────────────────────────────
四、方法名 ↔ 人话 对照表
───────────────────────────────────────────────────────────────────
mainloop / Update   → 游戏时钟，让时间流动
addday              → "再过了一天"
dayevent            → "今天该发生啥？查表+抽随机"
doevent(temp)       → "把这件事演给玩家看"
waittime0           → "先停 N 秒，到点再叫下一个动作"（延时器/分步刷新核心）
act1event / addeventlove → "和这个角色互动触发的剧情/感情事件"
getpost             → "去服务器问问有没有新事件"（联网刷新）
person.history      → 每个角色自己的"人生时间线"
