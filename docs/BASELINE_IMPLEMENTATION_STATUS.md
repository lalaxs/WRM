# 修仙放置游戏基础版实现状态与后续开发说明

## 1. 当前交付目标

当前阶段不再以“每个边缘输入都经过多轮安全审查”为推进条件，而以完成一套可以连续操作的基础玩法为目标：

1. 玩家可以挂机采集、生产、种植、养灵兽；
2. 玩家可以配置功法与战斗方案，挑战区域和副本并突破境界；
3. 世界中存在永久人物，玩家可以查看关系、进行社交、处理事件并选择宗门；
4. 玩家可以经历寿元、后代、传承与新一轮人生的基础流程；
5. 所有页面继续使用现有顶部状态栏、左侧页签、右侧内容区和弹层结构。

高级安全加固、极限性能测试、大量内容扩写和数值平衡不阻塞基础版完成，统一记录在本文末尾供后续 AI Agent 接手。

## 2. 已完成的基础系统

### 存档与挂机

- 单一版本化存档；
- 可序列化随机状态；
- 在线与离线共用同一模拟入口；
- 离线收益详情先展示，历史摘要进入事件页；
- 主行动槽与不占主行动槽的并行进度分开保存。

### 生活技能与洞府

- 采药、采矿、伐木、钓鱼、炼丹、炼器、烹饪、符箓、魅力、御兽、种植、阵法；
- 资源采集、生产配方、背包容量与出售；
- 灵田、阵法、灵兽基础管理；
- 魅力只拥有等级和经验，通过社交提升，没有额外精通。

### 战斗、功法与突破

- 普通区域战斗、副本波次、首领、战利品和重伤恢复；
- 最多五套战斗方案、装备绑定、三类补给和自动撤退；
- 四个功法槽、条件释放、功法学习与升级；
- 突破任务门槛、修为要求、丹药和事件增益；
- 普通战斗失败只会重伤，不会直接死亡；
- 玩家可见文案使用“与某人一起修炼”，不出现审核敏感字样。

### 人物世界基础

- schema v5 人物世界存档；
- 首次确定性生成 120 名永久人物；
- 40 人活跃圈与 80 人后台池；
- 8 个抽象地区，只作为列表、筛选和事件条件，不存在大地图；
- 5 个固定宗门；
- 双向独立的八维关系数据与事件驱动的关系阶段。

## 3. 已完成的基础社交与事件纵向流程

### 社交

- 已提供交谈、赠礼、陪伴、论道、出游、拜访、与某人一起修炼七种通用互动；
- 当前人物所属宗门可解锁现有宗门特色互动；
- 主动社交作为一次性主行动运行，完成后自动释放主行动槽；
- 社交完成后增加魅力经验、修为和双向独立关系数值，魅力仍没有精通；
- 魅力等级会提高正面关系收益并降低普通误会概率；
- 赠礼消耗与全部社交结果一次性结算，材料不足时不提交部分结果；
- 事件产生的互寄书信、寻找礼物、准备赴约等进度在并行队列中运行，不占主行动槽；
- 同一人物同时只能有一条并行社交，不同人物可以同时进行；
- 并行社交使用完整离线时间，到时若待决事件已满会保留为“已准备好”，容量释放后只晋升一次。

### 事件

- 已建立“事件摘要、待玩家决策、世界演变”三类保存数据；
- 待决策事件不超时、不覆盖，上限为 20 条；
- 事件实例保存已经渲染的中文正文和效果快照，内容库以后改版也不影响旧事件；
- 事件选项一次性原子结算，重复提交不会重复发放结果；
- 未知效果会使整个选项失败，不会只提交前半部分；
- 关系阶段变为好友、恋人、正式伴侣或分开时，会保存对应的已处理事件证据；
- 已提供 15 个基础中文模板，覆盖双向关系、恋爱阶段、解释/补偿/协商/退出冲突、五宗门与散修选择、具名并行后续、地区摘要和世界演变；
- 地区摘要和世界演变不受 20 条待决事件容量影响。

### 基础模块接口

- `core/social.js`：解析社交行动、判断人物与礼物是否可用、计算持续时间、原子结算奖励与关系、查询人物可用互动；
- `core/event-engine.js`：筛选并实例化模板、加入待决队列、原子处理选项、写入事件摘要与世界演变；
- `core/stage4-rules.js`：在 Stage 3 统一模拟之上接入一次性社交主行动、社交增益和并行社交，不创建第二套计时器；
- `content/event-templates.js`：保存冻结的人工中文事件模板，不执行在线文本生成；
- `core/stage4-state.js`：继续保存 v5 人物、关系、事件、宗门、社交增益与并行任务。

## 4. 已完成的基础人物、宗门与世界演变

### 人物自主生活

- 活跃人物每 15 分钟做一次基础决定，可以修炼、满足条件后尝试突破、前往抽象地区、与附近人物来往，也可能通过世界事件改变宗门归属；
- 后台人物每 6 小时进行一次简化决定，每人最多只查看 3 个稳定候选，不会把所有人物两两遍历；
- 活跃圈每人最多查看 8 个附近候选，后台人物与玩家产生联系后会在后续重分层时进入活跃圈；
- 人物年龄使用完整在线和离线时间，余下不足一年的时间继续保存；
- 人物达到寿元时当前阶段只记录提醒，不删除人物、不直接判定死亡，死亡、飞升与转世留给生命周期系统；
- 人物之间的关系数值保持双向独立；自主关系阶段变化必须由事件引擎留下已处理世界事件，不能由数值阈值直接改名分；
- 20 条待决事件已满时，只暂停新的玩家关键事件，人物修炼、旅行、关系摘要和宗门演变继续运行。

### 宗门

- 玩家开局为散修，第一次真正完成主行动后收到一条五宗门正式选择事件；
- 选择继续散修后，至少经过一个世界日才会再次收到选择；
- 加入、离开或更换宗门都通过事件选项结算，已经学习的生活技能、功法与等级不会重置；
- 太玄剑宗、百草谷、天工阁、灵兽山、清音宫五个宗门每天演变一次，不会消失，势力值最低为 1；
- 宗门保存领袖、基础职务、势力、声望，以及结盟、中立、竞争、敌对四种两两关系；
- 宗门只影响后续技能、功法、资源、任务和事件内容，不修改突破成功率。

### 世界事件调度

- 每个世界日确定性产生 5–10 条关键事件预算，每 2 小时尝试生成一条，达到当日预算后停止新增；
- 待玩家决定的事件仍然不超时、不覆盖，上限 20 条；
- 事件摘要最多保留最近 300 条详细记录，世界演变最多保留最近 500 条，旧记录按月份和类别压缩并保留数量与重要人物/宗门标识；
- 世界报告只记录新增待决数量、人物变化、宗门变化和演变数量，不把完整事件正文塞进离线结算层；
- 15 分钟活跃人物、6 小时后台人物、2 小时事件和 1 天宗门演变全部接在同一个统一模拟入口中，没有额外计时器；
- 基础验证已经覆盖 24 小时一次离线推进与 96 段在线推进保存结果一致。

## 5. 已完成的人物世界接口与页面

### 游戏接口

- `game.js` 已使用 `Stage5Rules` 组合既有 `Stage4Rules`，所有系统仍走同一个统一模拟入口，同时保留 Stage 1–4 原有接口；
- `events` 查询提供事件摘要、待决策、世界演变三段数据、数量、未读标记和稳定游标，离线报告只在查询时合并，不重复写入存档；
- `relationships / relationship` 提供人物搜索排序、身份资料、所在地区与宗门、关系阶段和八维双向关系；
- `social` 提供当前可用互动、耗时与基础收益、礼物选择、主行动进度和具名并行进度；
- `sects / sect` 提供五个固定宗门、玩家散修或入门状态、领袖、势力、名望、立场和由人物记录即时统计的门人数；
- `world` 提供抽象地区、人物、宗门、家族和世界变化卡片，只做列表与筛选，不包含地图和坐标；
- `startSocial` 使用唯一主行动槽，`chooseEvent` 原子处理一次选择，`markEventSectionRead` 只改变显示元数据。

### 现有 UI 框架中的四个页面

- 事件页已提供“事件摘要 / 待决策 / 世界演变”页签和事件选项按钮；
- 关系页已提供魅力说明、人物搜索排序、人物详情、八维双向关系、可用互动和并行进度；
- 宗门页已提供散修状态、五宗卡片和宗门数据，加入、离开或更换宗门统一引导到事件页，不提供直接切换按钮；
- 天下页已提供地区、人物、宗门、家族和最近变化卡片，以及“身边动态 / 天下传闻”筛选；
- 页面继续使用现有顶部状态栏、左侧页签、右侧内容区和弹层；窄屏按单列堆叠，主要操作按钮保持至少 44 像素高度；
- 根目录源码是唯一权威，Stage 4 运行时文件已进入发布同步清单并同步到 `release/`，`release/NIE` 保持原样。

## 6. Stage 5 基础已实现

### 生命周期与传承

- 为优先交付可操作基础版，当前生命周期与传承字段先由现有 schema v5 规范化并持久化；正式拆分为 schema v6 的迁移链留给后续加固阶段；
- 玩家年龄与寿元使用统一在线、离线时间推进，寿元将尽时进入不可跳过的安全缓冲；进入缓冲的瞬间弹出一次性「寿元将尽」提示弹窗(可稍后处理)，不再每帧自动检测，也不自动强制转生；
- 正式伴侣可以共同筹备具名传承仪式，进度不占主行动槽，完成后留下后代记录；
- 洞府中的一级传承殿已经提供概览、传承方案、后代和历代四个基础区块；
- 传承方案可以配置一级容量内的完整精通、功法、装备和资源种类；
- 玩家可以主动开始人生转换，进入寿元安全缓冲时也会弹出一次性提示引导其完成转换；
- 人生转换支持由成年后代继承或创建新身份；主动流程可取消，寿元流程不可取消；
- 新人生完整保留十二项生活技能的等级与经验，重置修为和本世临时状态；
- UI 继续使用原有顶部状态栏、左侧页签、右侧内容区与统一弹层根节点。

## 7. Stage 5 明确延期内容与后续工作

1. NPC 死亡、转世与飞升，以及相关完整生命周期结算；
2. 复杂亲属关系、前世人物重逢与跨世关系剧情；
3. 传承殿 2–5 级、完整资产继承和更细致的传承收益预览；
4. 更多生命周期事件、人物传记、宗门任务和世界演变内容；
5. 7 天以上离线模拟、1000 人物压力测试和存档体积优化；
6. 360×800、420×820 及更多设备的真实浏览器验收和截图验收；
7. 数值平衡、异常存档加固，以及更多头像、图标、音效和反馈动画。
8. 将当前基础字段正式升级为 schema v6，并补齐跨版本回滚、损坏存档恢复与迁移矩阵。

## 8. 开发边界

- 不替换现有 UI 总框架；
- 不制作大地图；
- 不添加手动点击释放功法；
- 不让社交等待占用额外挂机格子；
- 不让关系数值自动决定关系阶段；
- 不让宗门或任何社交增益直接修改突破概率；
- 不在普通战斗失败时触发角色死亡；
- 根目录源码为唯一权威，`release/` 只通过发布同步生成。
