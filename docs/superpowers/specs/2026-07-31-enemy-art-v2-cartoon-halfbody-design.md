# 敌人形象美术规范 v2：卡通化与统一半身姿态

日期：2026-07-31

## 1. 修订原因

首批 `enemy-v1-no-outline-xianxia` 样张验证出两个问题：

1. 整体比例与明暗切面仍接近缩小的角色立绘，不够卡通；
2. 人形敌人使用头至膝或全身构图，站姿和手臂动作各不相同，在 84px 战斗框中显得细长、零散且不统一。

v2 保留无描边、轻仙侠、大色块和敌人等级层次，集中修正卡通比例与人形构图。

正式修订风格名为：

```text
enemy-v2-cartoon-halfbody-xianxia
```

中文名称为“无描边轻仙侠·卡通半身敌人风”。

本规范在未冲突处继承
`docs/superpowers/specs/2026-07-31-enemy-art-asset-standard-design.md`；
发生冲突时以本文件为准。

## 2. 已确认的设计方向

比较过三种人形构图：

1. 统一半身收势：腰部以上、左前三分之四视角，双臂收在胸腹范围；
2. 正面徽章式半身：最整齐，但过于呆板，敌意和战斗感不足；
3. 斜肩攻击式半身：动势更强，但兵器差异会再次破坏统一性。

正式采用第一种。

## 3. 全体敌人的卡通化规则

### 3.1 比例

- 妖兽、虫灵、傀儡和兽类首领的头部相对 v1 放大约 15%–20%。
- 四肢相对 v1 缩短，并使用短、厚、圆的体块，不保留写实关节长度。
- 人形敌人只显示腰部以上，头部占可见主体高度约 30%–35%。
- 首领可以更宽、更重，但不能通过写实肌肉或复杂人体比例体现强度。
- 翼、角、耳、岩块和法相板等识别结构使用宽而少的大形，不使用细长碎片。

### 3.2 形状

- 圆形、椭圆和圆角梯形作为主要体块。
- 尖角只用于一个身份特征，例如兔背棘、雷罚使肩甲、法相板。
- 普通敌人控制在 3–5 个主要造型块。
- 精英与首领控制在 5–7 个主要造型块。
- 眼睛、手指、衣褶、毛簇、岩纹和翼纹都必须继续概括。
- 禁止小头长腿、宽肩窄腰的写实英雄比例。

### 3.3 渲染

- 无黑色描边、无线稿、无轮廓描边。
- 以纯净主色面为主，只允许一块亮面和一块暗面。
- 禁止连续渐变塑造体积、写实光影、厚涂和材质噪声。
- 普通敌人优先保留主色与一个强调色。
- 精英和首领可以增加一个等级强调色，但不能增加满身装饰。
- “卡通”来自比例、轮廓和色块，不使用腮红、星星眼、吐舌或夸张笑脸。

## 4. 统一人形半身姿态

所有人形、类人精英和人形法相使用同一基础模板。

### 4.1 固定构图

- 画面只显示头部至腰部下缘。
- 身体朝画面左侧转约 30°。
- 头部轻微转回玩家方向，保留双眼可读性。
- 脊柱直立，双肩基本等高，不使用大幅扭腰或冲刺姿态。
- 近侧前臂横收在下胸至上腹区域。
- 远侧手臂弯曲，手掌停留在胸口至上腹区域。
- 双手、武器、器物和法术都必须收在肩宽以内。
- 精英肩甲和首领背部结构可以延伸到肩宽的 1.35 倍，但不得遮挡头部、肩线和手臂收势。
- 手臂不得伸向画布边缘，不得张臂、挥砍或形成大对角线。
- 腰部下缘使用自然衣摆或能量结构收口，不出现被随意截断的腿。

### 4.2 允许变化

固定姿态不变，只允许以下身份差异：

- 头发、发冠和脸部情绪；
- 肩部轮廓；
- 袍服主色；
- 胸口核心；
- 收在双手之间或贴近前臂的小型器物；
- 与肩背相连的一个精英或首领结构。

### 4.3 禁止变化

- 不得改变身体朝向；
- 不得改变半身裁切高度；
- 不得把一名敌人画成全身或头至膝；
- 不得让某名敌人使用展开双臂、持长兵器、举手施法或向前冲刺的特殊姿势；
- 不得使用多人、分身或第二张脸；
- 不得用大量飘带、雷电或法相板改变基础身体剪影。

## 5. 首批七个敌人的 v2 处理

| enemyId | v2 处理 |
| --- | --- |
| `thornHare` | 头更大、腿更短、身体更像圆角豆形；背部只保留 3–4 枚宽棘 |
| `stonePuppet` | 岩块减少为 6–7 个圆角大块；拳和脚加大，关节缩短 |
| `soulMoth` | 头胸合并为紧凑圆形；翅膀变宽变短，每侧只保留一个大色纹 |
| `rogueCultivator` | 使用统一半身姿态；深酒红短袍；双手之间保留一个无字铜色护符块 |
| `thunderJudge` | 使用统一半身姿态；肩甲为唯一精英结构；短雷杖横收于胸腹，雷电只贴附前臂和杖 |
| `earthVeinApe` | 头部放大、前臂更短更厚；肩背岩脊减少；地脉纹合并为两至三块 |
| `myriadLawAvatar` | 使用统一半身姿态；中央人形保持清楚；肩后只保留 3–5 片相连宽法相板 |

三个人形敌人的差异必须来自服装、主色和一个结构焦点，不能来自站姿。

## 6. 输出与对比

v1 样张保留，不覆盖：

```text
docs/art/enemy-prototypes/2026-07-31-enemy-v1/
```

v2 样张输出到：

```text
docs/art/enemy-prototypes/2026-07-31-enemy-v2-cartoon/
```

每个敌人输出：

```text
{enemyId}-source.png
{enemyId}-preview.png
```

总览文件：

```text
enemy-v2-cartoon-contact-sheet.png
```

接触表每行必须包含：

- v1 的 84px 对照；
- v2 的 256px 透明底预览；
- v2 的 104px 桌面战斗框；
- v2 的 84px 竖屏战斗框；
- v2 的浅粉战斗卡效果。

## 7. v2 验收标准

### 7.1 全体

- 七个敌人第一眼比 v1 更卡通；
- 头部、拳脚、翼或核心等焦点在 84px 下更明显；
- 不出现写实人体比例、写实毛发、写实肌肉或复杂衣褶；
- 普通怪、精英和首领仍有清楚的强弱层次；
- 七张之间保持同一种无描边、低切面、轻仙侠卡通渲染。

### 7.2 人形

- `rogueCultivator`、`thunderJudge`、`myriadLawAvatar` 都是腰部以上半身；
- 三者身体角度、头部角度、肩线、手臂收势和裁切高度一致；
- 把三张转成纯色剪影后，基础人体轮廓应属于同一模板；
- 身份差异不依赖不同动作；
- 84px 下头部和肩部比手中物更醒目；
- 雷杖和护符不得超出主体肩宽；法相板可以延伸到肩宽的 1.35 倍，但不得遮挡统一的人体姿态。

### 7.3 技术

- 512×512 PNG RGBA 透明母版；
- 256×256 PNG RGBA 预览；
- 四角透明；
- 主体占画布 80%–88%；
- 视觉中心偏差不超过画布 3%；
- 无绿色或品红色色键边缘；
- 文件名与现有 `enemyId` 完全一致。

## 8. 本轮边界

本轮只重做并评审七张 v2 样张。

本轮不：

- 覆盖 v1 原型；
- 接入 `assets/enemy-portraits/`；
- 修改 `ui.js`、`styles.css` 或 `release/`；
- 批量生成其余敌人；
- 修改敌人名称、数值、阶级或剧情；
- 在用户确认 v2 前把样张作为正式资源。
