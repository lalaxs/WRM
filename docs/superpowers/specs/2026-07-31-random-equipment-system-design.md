# 随机词条战斗装备系统设计

日期：2026-07-31
状态：已批准，进入实施

## 1. 目标

为《我在修仙界万人迷》增加一套仅服务战斗的随机装备系统。系统保留类梅尔沃放置游戏“持续刷取、快速比较、方案切换”的低操作成本，同时提供比传统梅尔沃式数值装备更强的构筑深度。

核心体验是：

1. 战斗、首通、锻造和特殊内容持续产出有随机词条的装备实例。
2. 玩家围绕功法标签、资源循环、异常、治疗、护盾、召唤和阵法等方向构筑。
3. 装备没有硬性功法限制，只通过标签、共鸣和规则词条形成软联动。
4. 背包页就是装备工作台：顶部固定显示当前方案的八件装备，下方处理通用背包。
5. 玩家可以强化装备、锁定一条词条后重铸其余词条，但普通装备不能提升品质。

生活装备不纳入本系统。未来若增加类似《银河奶牛放置》的生活装备，应使用独立的内容定义和效果结算域，但继续占用同一个通用背包容量。

## 2. 设计原则

- **命名底材 + 随机词条 + 标签共鸣**：装备的辨识度来自固定底材，长期刷取来自随机词条，构筑方向来自共鸣和稀有规则。
- **完整属性池开放**：全部战斗属性都可以出现在全部槽位，槽位只影响权重，不设置绝对禁区。
- **规则效果受控**：装备可以修改功法循环和触发规则，但不能提供需要玩家手动释放的独立主动技能。
- **实例不可堆叠**：每件随机装备都是独立实例；材料和消耗品继续按物品 ID 堆叠。
- **确定性与可存档**：生成、重铸和强化结果必须由可序列化随机状态驱动，读档不能改变已生成结果。
- **竖屏优先**：主布局以手机竖屏为基准，不从桌面布局反向压缩。

## 3. 系统边界

### 3.1 静态内容

新增三个静态注册表：

- `EquipmentBaseDefinition`
- `AffixDefinition`
- `ResonanceDefinition`

静态定义不进入存档。存档只保存实例、方案引用和操作进度。

### 3.2 装备实例

每件装备实例保存：

```js
{
  instanceId: "eq_...",
  baseId: "mystic_iron_sword",
  quality: "legendary",
  affixes: [
    { affixId: "flat_attack", tier: 3, rolledValue: 58 },
    { affixId: "crit_chance", tier: 2, rolledValue: 0.06 }
  ],
  enhancement: {
    level: 8,
    pityFailures: 0
  },
  lockedAffixIndex: null,
  favorite: false,
  source: {
    type: "combat_drop",
    sourceId: "enemy_bandit_swordsman",
    acquiredAt: 123456
  }
}
```

不在实例中重复保存以下派生数据：

- 底材名称、槽位、图标和基础属性
- 强化后的最终基础属性
- 共鸣总数与已激活阈值
- 综合评分
- 词条说明文本

这些数据统一由静态定义和实例字段计算。

### 3.3 通用背包

背包占用计算为：

```text
占用格数 = 非空堆叠物品种类数 + 装备实例数量
```

规则：

- 装备中、收藏中、被方案引用的实例仍占用背包格。
- 不建立独立装备仓库或装备容量。
- 背包满时，新生成的不可堆叠装备不会进入背包。
- 背包满不会中断战斗；系统写入明确日志，装备永久丢失。
- 生成流程必须先确定完整装备结果，再检查容量，避免容量状态影响随机序列。

## 4. 八个装备槽

最终槽位为：

1. 武器 `weapon`
2. 头冠 `head`
3. 法袍 `robe`
4. 护腕 `bracer`
5. 腰带 `belt`
6. 靴履 `boots`
7. 饰品 `accessory`
8. 法宝 `artifact`

解锁节奏：

- 练气：武器、法袍、饰品，共 3 槽。
- 筑基：增加头冠、护腕，共 5 槽。
- 金丹：增加腰带、靴履，共 7 槽。
- 元婴：增加法宝，达到 8 槽。
- 后续境界不再增加新槽。

槽位倾向：

| 槽位 | 高权重方向 |
| --- | --- |
| 武器 | 攻击、命中、暴击、伤害、穿透、功法标签 |
| 头冠 | 真气、命中、控制命中、控制抗性、循环 |
| 法袍 | 气血、防御、减伤、受治疗、护盾 |
| 护腕 | 攻速、暴击、异常强度、攻击、触发效果 |
| 腰带 | 气血、防御、减伤、控制抗性、异常抗性 |
| 靴履 | 闪避、行动间隔、控制抗性、生存条件词条 |
| 饰品 | 真气恢复、治疗、护盾、异常、构筑工具 |
| 法宝 | 低基础数值、高构筑词条、高稀有词条和共鸣权重 |

全部属性仍可出现在全部槽位。上表只用于抽取权重和内容风格。

## 5. 命名底材

每个底材固定包含：

```js
{
  id,
  name,
  slot,
  realmBand,
  baseStats,
  implicitEffect,
  styleTags,
  affixWeightProfile,
  resonanceId,
  sourceRules,
  iconKey
}
```

底材规则：

- 同一底材的名称、槽位、境界档、基础属性、固有效果和图标固定。
- 基础属性为 1 至 3 项。
- 每件底材最多提供 1 点共鸣。
- 武器可以带剑诀、炼体、丹毒、符法、阵法、御兽、魂、水等风格标签。
- 风格标签只提供软联动，不能禁止其他功法使用。
- 法宝不提供手动主动技能，只提供被动规则和触发效果。
- 展示名使用 `[品质] 底材名 +强化等级`，不把随机词条拼接进名称。

## 6. 品质、词条数量与词条阶级

品质决定词条数量：

| 品质 | 普通词条槽 |
| --- | --- |
| 普通 | 0 |
| 精良 | 1 |
| 稀有 | 2 |
| 史诗 | 3 |
| 传说 | 4 |
| 神话 | 特殊内容手工定义 |

传说装备可以在 4 个词条槽中将 1 个替换为稀有词条。稀有词条不是额外的第五条。

词条阶级为 T1 至 T6。装备境界档决定可出现的最高阶级：

| 境界档 | 可用词条阶级 |
| --- | --- |
| 练气 | T1–T2 |
| 筑基 | T1–T3 |
| 金丹 | T2–T4 |
| 元婴 | T2–T5 |
| 化神及以上 | 开放 T6 |

品质只调整高阶词条权重，不突破境界档上限。词条生成后保存实际数值，后续平衡表调整不能改变已获得装备。

## 7. 属性词条与构筑词条

### 7.1 数值词条

装备属性池以 `content/combat-lexicon.js` 为统一命名源，覆盖：

- 最大气血、最大真气
- 攻击、防御、命中、闪避
- 暴击率、暴击伤害
- 行动间隔缩减
- 伤害减免
- 治疗强度、受治疗
- 护盾强度
- 真气恢复
- 控制命中、控制抗性
- 异常强度、异常抗性
- 净化强度
- 仇恨获取、保护权重

另外允许由战斗结算器消费的派生修饰：

- 伤害提高
- 防御忽略
- 条件增伤
- 标签功法增伤
- 对异常目标增伤
- 治疗或护盾触发后的短时增益

行动速度词条保存为比例缩减，不直接保存整数 tick。

### 7.2 构筑词条

构筑词条占用普通词条槽，每件装备最多 2 条。构筑词条只引用统一标签和战斗事件，不绑定某一本具体功法。

允许的事件例子：

- 施放某标签功法
- 完成一次主动功法循环
- 暴击
- 造成或承受异常
- 治疗、获得护盾、护盾破裂
- 消耗或恢复真气
- 灵兽行动
- 阵法触发

所有触发词条必须明确：

```text
触发事件、触发条件、目标、数值、持续时间、
叠层上限、内置冷却、战斗日志文本
```

### 7.3 稀有词条

稀有词条主要来自传说装备、Boss、首通、宗门、事件或传承内容。它可以轻量改变规则，例如：

- 某类功法暴击后降低下一次同标签功法的真气消耗。
- 完成功法循环后提前某个标签的下一次可用时间。
- 护盾破裂时净化一层控制并获得短时减伤。
- 对带指定异常的目标，将部分伤害转化为另一种效果。

稀有词条不得：

- 增加需要手动点击的新技能。
- 无上限地自我触发。
- 绕过统一事件、叠层或内置冷却系统。

## 8. 标签共鸣

每件装备最多贡献 1 点共鸣。共鸣点来自底材或某一条词条，两者不能同时存在。

共鸣只设置 2 件与 4 件阈值，不设置 6 件或 8 件阈值。八个槽位允许常见的 `4 + 2` 构筑，同时保留两件纯数值装备。

首批共鸣方向：

- 剑意
- 周天
- 生息
- 守御
- 异变
- 阵枢
- 灵契
- 和鸣

平衡目标：

- 2 件效果只负责支撑玩法，不完成整个构筑。
- 4 件效果在适配战斗中带来约 10%–18% 的有效收益。
- 共鸣不能同时成为伤害、生存和资源三方面的最优解。
- 不带共鸣的高数值装备必须保持可用。

## 9. 获取与锻造

来源分工：

- 普通敌人：低品质基础装备与常见底材。
- 精英：提高品质和高阶词条权重。
- Boss：专属底材、稀有词条权重和共鸣方向。
- 首通：确定性底材或高品质保底。
- 锻造：玩家选择底材，品质和词条随机。
- 宗门、NPC、事件、传承：提供特色底材或规则词条。

锻造技能和熟练度可以：

- 解锁底材。
- 提高品质与高阶词条权重。
- 降低时间和材料消耗。

锻造技能不能直接提供角色战斗属性。

普通装备品质生成后固定，不能升品。

## 10. 强化

强化上限为 `+15`，只放大底材基础属性，不放大词条：

```text
强化后的基础属性 = 原基础属性 × (1 + 0.02 × 强化等级)
```

`+15` 时基础属性总计提高约 30%。

成功率与保底：

| 阶段 | 基础成功率范围 | 最多连续失败 |
| --- | --- | --- |
| +1–+3 | 100% | 0 |
| +4–+6 | 75%–90% | 3 |
| +7–+9 | 50%–70% | 4 |
| +10–+12 | 30%–45% | 6 |
| +13–+15 | 15%–25% | 8 |

规则：

- 失败消耗材料。
- 失败不降级、不损坏、不销毁装备。
- 当前等级的失败次数写入实例。
- 达到该等级保底次数时下一次必定成功。
- 成功后清空当前等级失败计数。
- 保护符提高成功率，但不能超过 100%。

## 11. 重铸

重铸保留：

- 底材
- 境界档
- 品质
- 强化等级和保底进度
- 词条槽数量
- 收藏与来源信息

玩家可以锁定 1 条词条，其余词条全部重抽。

规则：

- 固有效果不能被重铸。
- 未锁定的稀有词条可以消失。
- 重铸可以重新抽到稀有词条。
- 来自词条的共鸣点会随该词条一起改变。
- 重铸前显示受影响的战斗方案。
- 所有重铸结果由存档随机状态确定。

## 12. 出售、分解与引用保护

首版提供手动出售和批量分解，不提供自动分解。

- 出售获得通用货币。
- 分解获得锻造材料。
- 收藏装备不能出售或分解。
- 被任意战斗方案引用的装备不能出售或分解。
- 同一实例可以被多个主角方案引用。
- 重铸被多个方案引用的实例时必须显示受影响方案。

NPC 装备独立保存在 NPC 档案中，不进入玩家背包。NPC 使用同一套底材、词条、强化和共鸣规则，但装备选择由模拟逻辑自动完成，玩家只能通过赠礼等间接影响。

## 13. 战斗方案与战斗快照

战斗方案保存八个 `instanceId`：

```js
equipment: {
  weapon: null,
  head: null,
  robe: null,
  bracer: null,
  belt: null,
  boots: null,
  accessory: null,
  artifact: null
}
```

开始战斗时，快照必须冻结：

- 八个装备实例的完整数据
- 对应底材定义所需字段
- 强化后的基础属性
- 全部词条效果
- 共鸣计数和已激活阈值
- 由装备注入的规则触发器

战斗中修改装备只影响下一场战斗，不能改变当前快照。

## 14. 竖屏背包与装备交互

主基准为约 `390 × 760` 的手机竖屏画布。

### 14.1 页面结构

- 保留当前游戏顶栏、修为/行动状态、左侧导航和浅紫卡片语言。
- 进入背包后，右侧内容区顶部固定显示当前战斗方案的装备栏。
- 八个槽位使用四列两行。
- 装备栏下面显示现有背包分类页签、容量、筛选和四列背包网格。
- 装备栏不随背包滚动；只有下方背包内容滚动。
- 背包分类横向滚动，不能压缩到不可点击宽度。

### 14.2 点击已穿戴装备

点击上方装备槽只显示锚定该槽位的轻量浮层 tips：

- 图标、名称、品质、强化等级
- 主要属性、构筑或稀有词条摘要
- `卸下` 与 `查看详情`

tips 使用浮层定位，不参与文档布局，不拉高装备栏或背包底图。点击空白处关闭。浮层必须限制在右侧内容区内，不能被屏幕边缘裁切。

### 14.3 点击背包装备

点击背包中的任意装备，继续使用项目现有居中物品详情弹窗，不引入新的“选中后再点上方槽位”状态。

装备详情弹窗增加：

- 完整基础属性与随机词条
- 当前方案对应槽位的替换差值
- 共鸣阈值变化
- 装备、强化、重铸、分解操作

竖屏下操作按钮使用两列布局。

点击 `装备` 后：

1. 自动装备到当前方案唯一兼容的槽位。
2. 原槽位装备留在通用背包。
3. 装备栏立即刷新。
4. 若当前正在战斗，提示“下一场战斗生效”。

### 14.4 图标规格

- 美术源文件：256×256，透明背景，主体位于约 80% 安全区。
- 背包格：沿用现有 34×34 图标显示区。
- 装备栏：38×38 图标显示区。
- 详情弹窗：沿用现有 60×60 容器、54×54 图像。
- 战利品格：沿用现有 28×28 图标。
- 品质底色、强化等级、新获得、收藏和方案引用均由 UI 叠加，不能烘焙进图标文件。
- 每个命名底材通过 `iconKey` 指向固定图标；随机词条不会改变图标。

## 15. 存档迁移

旧存档仍使用武器、护甲、饰品三个按物品 ID 堆叠的装备类型。迁移必须：

1. 为每个旧装备数量创建等量装备实例。
2. 使用稳定顺序和可复现迁移种子生成实例 ID 与初始词条。
3. 将旧方案中的 `itemId` 替换为对应实例 `instanceId`。
4. 将旧 `armor` 映射到 `robe`。
5. 新增槽位初始化为 `null`。
6. 从堆叠物品表移除已实例化的装备数量。
7. 保持通用背包容量合法；迁移本身不得因容量不足丢失旧装备。
8. 迁移完成后写入装备系统版本号，保证幂等。

## 16. 错误处理与不变量

- 未知底材、未知词条或非法实例不得参与战斗计算。
- 方案引用缺失实例时按空槽处理并记录诊断信息。
- 重复 `instanceId` 在规范化时保留第一件并重新生成后续冲突 ID。
- 非法强化等级钳制到 0–15。
- 非法品质、词条阶级和数值回退到安全默认值。
- 强化、重铸、出售、分解和装备命令必须是原子操作；校验失败不得部分扣除材料或改变装备。
- 当前战斗快照不能持有可变背包对象引用。
- 任何实例最多贡献 1 点共鸣。
- 任何实例最多拥有 2 条构筑词条和 1 条稀有词条。

## 17. 测试策略

### 17.1 领域测试

- 相同随机种子生成完全相同的实例。
- 品质对应正确词条数量。
- 境界档限制词条阶级。
- 槽位权重生效但不形成属性禁区。
- 单件装备不会贡献超过 1 点共鸣。
- 2/4 共鸣阈值正确激活。
- 强化失败不降级，保底次数正确。
- 锁定词条在重铸后完全不变。
- 未锁定稀有词条可以消失。
- 背包容量正确计算堆叠种类和装备实例。
- 背包满时装备丢失且战斗继续。
- 被方案引用或收藏的装备不能出售、分解。
- 战斗快照不受战斗中换装影响。

### 17.2 迁移测试

- 三槽旧存档可以迁移到八槽实例方案。
- 多数量旧装备全部转换且不丢失。

## 18. 首版范围外

- 生活装备。
- 装备升品。
- 自动出售或自动分解。
- 玩家手动释放的装备主动技能。
- 装备交易、拍卖或跨角色仓库。
- 6 件、8 件传统套装效果。
- 大规模神话装备内容；首版只保留数据接口。
