# 顶部五资源图标设计

日期：2026-07-30

## 目标

为游戏顶部资源栏的五项长期状态生成并接入同一套图标：

1. 灵石
2. 精气
3. 心情
4. 声望
5. 寿元

保留五项现有或规划中的数据语义。精气虽然当前只在修炼行动中增减，仍作为后续“与他人修炼”消耗资源保留；本次不实现该玩法。

## 视觉方案

采用现有 `v4-no-outline` 物品图标规范：

- 简约扁平矢量感；
- 单一具象主体；
- 无描边、无边框、无文字、无装饰粒子；
- 低阴影和克制高光；
- 主体居中，占画布约 72%–82%；
- 透明背景；
- 在顶部约 14px 的最终显示尺寸下仍能通过轮廓和主色区分。

五项造型与主色固定如下：

| 资源 | 造型 | 主色 | 识别重点 |
| --- | --- | --- | --- |
| 灵石 | 淡青六棱晶币 | 淡青、青绿 | 硬质切面和晶石轮廓 |
| 精气 | 蓝白凝气旋涡 | 天蓝、冰白 | 向心旋转的气流轮廓 |
| 心情 | 粉色心形花瓣 | 桃粉、浅玫红 | 心形与柔软花瓣感 |
| 声望 | 紫金宗门名牌 | 紫色、少量暖金 | 竖向玉牌/令牌轮廓 |
| 寿元 | 青叶寿桃 | 桃粉、嫩绿 | 寿桃和单片青叶 |

不使用抽象符号或统一圆形徽章，避免小尺寸下语义混淆，也避免引入与现有物品图标不一致的 UI 外框。

## 资产与生成

使用内置图像生成工具逐项生成五张独立源图。每张源图使用纯色抠图背景，本地移除背景并验证透明边缘。

最终项目资产放在：

```text
assets/resource-icons/100/
assets/resource-icons/50/
```

文件名固定为：

```text
lingshi.png
jingqi.png
mood.png
shengwang.png
shouyuan.png
```

100px 文件作为标准资源，50px 文件用于顶部 UI。两档均为 RGBA PNG，四角透明、主体居中。不得覆盖 `assets/item-icons/` 中已有的物品图标。

## 顶部栏接入

在 `ui.js` 中将现有彩色圆点替换为五项资源的 `<img>` 图标，并把寿元加入资源栏。排列顺序为：

```text
灵石 → 精气 → 心情 → 声望 → 寿元
```

每项继续保留数值和中文 `title`。寿元显示剩余年数；飞升后的无限寿元显示 `∞`。`game.js` 的顶部查询已经暴露 `shouyuan` 和 `shouMax`，UI 直接读取查询结果，不新增可变状态，也不绕过 `GameAPI`。

在 `styles.css` 中：

- 图标使用紧凑固定尺寸，目标约 14px；
- 保持现有紫色资源胶囊底色和白色数字；
- 缩减必要的横向间距，保证 390px 竖屏下五项与角色名同排且不溢出；
- 不增加顶部栏高度，不遮挡境界、修为条或突破按钮。

## 数据与行为边界

- 灵石、精气、心情、声望继续读取 `info.pills`。
- 寿元读取 `info.shouyuan`。
- 本次只改变展示，不修改资源产消规则、存档结构、模拟推进或寿元结算。
- 精气后续用途只作为产品约束记录，不在本次添加“与他人修炼”命令或消耗逻辑。

## 验证

新增或扩展自检以覆盖：

- 五项 100px/50px PNG 均存在且尺寸正确；
- PNG 带 alpha，四角透明，主体居中；
- 顶部栏创建五个图标，不再创建旧彩色圆点；
- 五项数值正确刷新，寿元有限值与 `∞` 均正确显示；
- 390×844 竖屏下顶部五项无溢出、重叠或断行；
- 图标无明显抠图色边，并且 14px 下仍可区分；
- release 同步与 H5 打包包含新资源。

完成后运行相关 UI/资源自检、`npm run sync-release`、release 同步检查和 H5 包检查，并在浏览器中截图复核顶部栏。
